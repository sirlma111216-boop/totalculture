# 확장 설계

## 현재 경계

- React / TypeScript UI, Leaflet / OpenStreetMap / markercluster 지도.
- `domain.mjs`: 거리·필터·백업 검증·예산 계산. UI와 분리된 순수 함수.
- `catalog.mjs`: 두 공공 데이터 형식을 공통 Place 모델로 정규화.
- Pages Functions: 인증키 보호, 자료 조회·캐시, 명시적 위치 검색.
- `research.json`: 사람이 공식 공개 안내를 확인한 초기 시설/지원 정보.
- localStorage: 현재 개인 워크스페이스. 이 단계에 공동 편집을 넣지 않음.

## 공유 아카이브로 확장

현재 Place.id는 출처 ID 또는 UUID입니다. 추후 다음 엔터티를 분리합니다.

1. Venue: 물리적 장소, 위치, 공개 연락처.
2. Offering: 전시·공연·체험·대관 상품. 장소와 1:N.
3. Schedule: 운영일·회차·접수기간. 공지된 기간과 실제 운영 회차를 분리.
4. Observation: 확인자, 확인시각, 근거 URL 또는 전화 확인 요약, 유효기간.
5. Workspace: 개인 보관함·계획·메모. 공유 데이터와 분리.
6. Contribution: 사용자 제안, 검토 대기, 승인, 반려. 검증되지 않은 변경을 공식 정보에 즉시 덮어쓰지 않음.

D1 또는 PostgreSQL repository를 현재 저장 계층 대신 주입할 수 있습니다. 공개 시설 데이터와 개인 메모를 별도 테이블/권한으로 분리하고, 로그인·역할·감사로그·변경 충돌 해결을 먼저 구현합니다. 브라우저의 개인 메모를 공유 아카이브로 자동 업로드하지 않습니다.

예약 상태는 Offering 또는 Schedule 단위의 시점 정보입니다. 기관 전체의 예약 가능 여부를 하나의 boolean으로 표현하지 않습니다. 지금의 상태 직접 확인일·근거·수정 이력이 이 확장의 기반입니다.

기기 간 동기화, 로그인, 사용자 간 공유, 기관의 실시간 좌석/결제 API는 현재 미구현입니다.
